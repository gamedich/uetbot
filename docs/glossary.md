# Глоссарий предметной области и технологий проекта UETBot

В данном документе приведены ключевые термины, сокращения и концепции, используемые при разработке, эксплуатации и документировании цифровой экосистемы МУП «Ульяновскэлектротранс».

| № | Термин | Английский эквивалент | Определение |
|:---:|---|---|---|
| **1** | **МУП «УЭТ»** | MUP "UET" | Муниципальное унитарное предприятие «Ульяновскэлектротранс» — основной оператор городского электрического пассажирского транспорта г. Ульяновска (трамвайные и троллейбусные перевозки). |
| **2** | **Подвижной состав** | Rolling stock | Совокупность транспортных единиц предприятия (трамвайные вагоны 71-911ЕМ «Львёнок», Татра Т3, троллейбусы), предназначенных для перевозки пассажиров по установленной маршрутной сети. |
| **3** | **Маршрут** | Transit route | Установленный и оборудованный путь следования подвижного состава между начальным и конечным остановочными пунктами по утвержденному расписанию. |
| **4** | **Расписание движения** | Transit schedule | График движения подвижного состава, регламентирующий время отправления, прибытия и интервалы между рейсами на каждом остановочном пункте. |
| **5** | **Диспетчер движения** | Transit dispatcher | Должностное лицо службы движения МУП «УЭТ», осуществляющее оперативное регулирование движения подвижного состава, перераспределение выпусков и оповещение об аварийных ситуациях. |
| **6** | **FSM (Конечный автомат)** | Finite State Machine | Математическая и программная модель управления последовательными шагами диалога с пользователем (состояния анкеты, обращений и подачи резюме). |
| **7** | **WAL-mode (SQLite)** | Write-Ahead Logging | Режим журналирования базы данных SQLite, при котором изменения записываются в отдельный WAL-файл, позволяя параллельно читать данные без блокировки пишущей транзакции. |
| **8** | **Conventional Commits** | Conventional Commits | Соглашение о стандартизации формата сообщений коммитов в Git (`feat:`, `fix:`, `docs:`, `chore:`, `BREAKING CHANGE:`) для автоматизации генерации версий и ченджлогов. |
| **9** | **SemVer (Семантическое версионирование)** | Semantic Versioning | Стандарт нумерации версий программного обеспечения формата `MAJOR.MINOR.PATCH`, отражающий степень совместимости изменений (`v1.8.0`). |
| **10** | **CI/CD** | Continuous Integration / Continuous Deployment | Методология непрерывной интеграции и доставки ПО с автоматизированным запуском линтеров (Ruff, Flake8), статического анализа (mypy), тестов и сборки документации при каждом коммите. |
| **11** | **Branch Protection** | Branch Protection | Механизм защиты критических веток (`main`, `release/*`) в системе контроля версий GitHub, запрещающий прямой пуш в ветку и требующий успешного прохождения проверок CI/CD и код-ревью. |
| **12** | **Telegram Mini App (TMA)** | Telegram Mini App | Веб-приложение на технологиях HTML5/CSS/JavaScript, запускаемое внутри клиента Telegram с передачей криптографически подписанных параметров сессии (`initData`). |
| **13** | **152-ФЗ РФ** | Federal Law No. 152-FZ | Федеральный закон «О персональных данных», регламентирующий правовые основания обработки, защиты, хранения и безвозвратного уничтожения ПДн граждан РФ (включая Приказ РКН №179). |
| **14** | **RBAC** | Role-Based Access Control | Ролевая модель разграничения доступа, при которой права пользователя определяются назначенной ему ролью (`superadmin`, `hr`, `tech`, `depot`, `applicant`). |
| **15** | **Пул дескрипторов соединений** | Connection Pool | Механизм повторного использования открытых файловых дескрипторов и соединений с базой данных для исключения утечек ресурсов ОС и снижения задержки (latency < 200 ms). |
| **16** | **Long Polling** | Long Polling | Технология взаимодействия с Bot API, при которой клиент удерживает HTTP-соединение с сервером до появления новых событий, исключая необходимость открытия внешних входящих портов. |
| **17** | **Webhook** | Webhook | Способ доставки входящих обновлений от мессенджера через обратный HTTP POST-запрос на публичный защищенный адрес сервиса по протоколу HTTPS. |
| **18** | **Санитизация и экранирование** | HTML Escaping / Sanitization | Преобразование опасных управляющих символов (`<`, `>`, `&`, `"`, `'`) в безопасные HTML-сущности для предотвращения XSS и HTML-инъекций в сообщениях Telegram. |
| **19** | **Defense in Depth** | Defense in Depth | Эшелонированная система информационной безопасности, организующая многоуровневые барьеры защиты (сеть, ОС, веб-сервер, приложение, база данных). |
| **20** | **Изоляция административного контура** | Admin Contour Isolation | Архитектурный принцип полного исключения привилегированных команд управления хостом и VCS (Git, bash) из публичного интерфейса бота и их размещение строго в изолированном SSH-контуре сервера. |
