# ADR 004: Архитектура медиа-шлюза и передачи вложений (VK ↔ Telegram)

* **Статус:** Accepted
* **Дата:** 2026-09-16
* **Автор:** Крючков И. К.

## Контекст
При найме на транспортное предприятие соискатели отправляют фотографии документов (водительские удостоверения, дипломы, трудовые книжки) и готовые резюме в форматах PDF/DOCX. Кадровики со своей стороны отправляют схемы проезда к депо, расписания и памятки. Требуется организовать надежную двустороннюю передачу медиаматериалов между ВКонтакте и Telegram с соблюдением требований 152-ФЗ РФ.

## Рассмотренные альтернативы
1. **Сохранение медиафайлов на локальный диск сервера**  
   *Недостатки:* риск утечки персональных данных соискателей, засорение дискового пространства, повышенные требования к безопасности файловой системы по 152-ФЗ.
2. **Передача исключительно внешних URL ссылок CDN**  
   *Недостатки:* ссылки CDN ВКонтакте имеют ограниченный срок жизни, а Telegram API часто возвращает ошибку `Wrong HTTP URL` при задержках CDN.
3. **Потоковая передача в оперативной памяти (In-Memory Streaming)**  
   *Решение:* Скачивание и загрузка файлов через бинарные потоки `io.BytesIO` / `BufferedInputFile` без сохранения на физический диск.

## Решение
1. **Потоковая передача через память (`io.BytesIO`):** файлы передаются напрямую между сетью ВКонтакте и Telegram Bot API в RAM-буфере. После отправки буфер очищается сборщиком мусора Python, что исключает утечки ПДн с диска.
2. **Алгоритм выбора максимального разрешения фото:** выборка из массива `sizes` ВКонтакте по максимальной площади ($width \times height$) с фильтрацией объектов, содержащих прямой URL.
3. **Четырёхшаговый алгоритм загрузки в VK API:**
   $$\text{photos.getMessagesUploadServer} \rightarrow \text{HTTP POST (multipart)} \rightarrow \text{photos.saveMessagesPhoto} \rightarrow \text{messages.send (attachment)}$$
4. **Сетевая устойчивость (Exponential Backoff):** циклы опроса Long Poll снабжены экспоненциальной задержкой ($1 \rightarrow 2 \rightarrow 4 \rightarrow 8 \rightarrow \dots \rightarrow 30$ сек) при сетевых сбоях для предотвращения блокировок IP.

## Последствия
* **Положительные:**
  * Полное соответствие требованиям 152-ФЗ (отсутствие временных файлов ПДн на диске).
  * Возможность кадровикам и соискателям обмениваться документами и фото прямо в окне чата.
  * Высокая отказоустойчивость при нестабильном интернет-канале.
* **Отрицательные:**
  * Повышенное кратковременное потребление оперативной памяти при одновременной пересылке нескольких крупных файлов (до 50 МБ).
