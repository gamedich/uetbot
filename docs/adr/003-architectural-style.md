# ADR 003: Архитектурный стиль приложения

* **Статус:** Accepted
* **Дата:** 2026-09-16
* **Автор:** Крючков И. К.

## Контекст
Определение внутренней структуры модулей системы для предотвращения смешивания сетевого кода мессенджеров, бизнес-логики анкетирования и слоя сохранения данных.

## Рассмотренные альтернативы
1. **Монолитный однофайловый скрипт**
2. **Слоистая модульная архитектура (Layered Architecture)**
3. **Микросервисная архитектура**

## Решение
Применение **слоистой модульной архитектуры (Layered Architecture)**.

## Обоснование
Разделение приложения на независимые уровни:
1. **Уровень адаптеров мессенджеров:** обработчики событий Telegram (aiogram) и ВКонтакте (Long Poll API).
2. **Уровень сервисов и бизнес-логики:** машина состояний FSM, валидация полей (телефон, возраст), маршрутизация обращений соискателей.
3. **Уровень данных (DAL / Data Access Layer):** репозиторий `database.py`, инкапсулирующий SQL-запросы, миграции и горячее резервное копирование.

Это исключает дублирование логики опроса между ботами и изолирует компоненты друг от друга.

## Последствия
* **Положительные:**
  * Независимое развитие, обновление и тестирование каналов доставки сообщений.
  * Возможность безболезненной замены SQLite на PostgreSQL без изменения кода хэндлеров.
* **Отрицательные:**
  * Увеличение количества файлов и интерфейсных слоев по сравнению с однофайловым скриптом.
