# ADR 002: Выбор СУБД и организация слоя хранения данных (Соответствие 152-ФЗ РФ)

* **Статус:** Accepted
* **Дата:** 2026-09-17
* **Автор:** Крючков И. К.

## Контекст
Проектирование хранилища данных анкет соискателей, ролевой модели (HR / Администраторы) и состояний пользователей на этапе разработки и внедрения MVP в соответствии с требованиями Федерального закона № 152-ФЗ «О персональных данных».

## Рассмотренные альтернативы
1. **SQLite (с оптимизацией WAL, aiosqlite и неблокирующим доступом)**
2. **PostgreSQL**
3. **MongoDB**

## Решение
Выбрана реляционная СУБД **SQLite** в режиме **WAL (Write-Ahead Logging)** с асинхронным доступом через `aiosqlite` и неблокирующий пул потоков (`asyncio.to_thread`).

Слой данных разделен на две независимые базы:
* `resumes.db` — основная база реальных соискателей.
* `resumes_test.db` — изолированная тестовая база (диапазон тикетов #900001+).

### Соответствие требованиям 152-ФЗ РФ:
1. **Фиксация согласия (ст. 9 152-ФЗ):** В схемы таблиц `candidates` и `inquiries` добавлено обязательное поле `consent_timestamp TIMESTAMP`, фиксирующее точное время подтверждения согласия субъекта персональных данных через инлайн-кнопку «Согласен».
2. **Полное уничтожение ПДн (ст. 21 152-ФЗ):** Реализован асинхронный метод `delete_candidate_152fz`, который:
   * Активирует режим `PRAGMA secure_delete = ON` (гарантированное затирание удалённых страниц нулями на диске).
   * Безвозвратно удаляет запись соискателя из `candidates`.
   * Каскадно удаляет связанные обращения из `inquiries` и активные сессии из `active_dialogs`.
   * Формирует юридический аудит-протокол уничтожения данных для кадровой службы.
   * Направляет официальное уведомление субъекту ПДн о прекращении обработки данных согласно ч. 7 ст. 21 152-ФЗ.

## Обоснование
Отсутствие накладных расходов на развертывание и администрирование отдельного сервера СУБД при локальном запуске и защите проекта, встроенная поддержка ACID-транзакций, достаточная производительность для объема до $10^4$ анкет в рамках проекта. Режим WAL исключает взаимные блокировки при параллельном чтении и записи.

## Последствия
* **Положительные:**
  * Полное соответствие требованиям ст. 9 и ст. 21 Федерального закона № 152-ФЗ РФ.
  * Нулевая сложность конфигурации окружения (вся база хранится в одном файле).
  * Быстрое создание горячих резервных копий (`backup_database`) без остановки бота.
  * Безопасное уничтожение ПДн без возможности восстановления forensic-утилитами (`secure_delete = ON`).
* **Отрицательные:**
  * Ограничения на запись при экстремально высокой интенсивности параллельных транзакций (потребует миграции на PostgreSQL при переходе в распределённый кластер).
