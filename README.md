# Многоканальный HR-сервис МУП «Ульяновскэлектротранс»

Промышленный программный комплекс автоматизации рекрутинга, первичного анкетирования и оперативного взаимодействия с соискателями для Муниципального унитарного предприятия «Ульяновскэлектротранс» (г. Ульяновск).

Сервис поддерживает одновременную работу через **Telegram**, **ВКонтакте** и корпоративный мессенджер **МАКС (VK Teams / MyTeam)** с централизованной обработкой анкет и обращений в едином кадровом центре. Разработан в строгом соответствии с требованиями Федерального закона № 152-ФЗ «О персональных данных».

---

## 🌟 Ключевые возможности

* **Мультиканальный приём анкет:** соискатели могут заполнять анкету и задавать вопросы из Telegram, VK или МАКС. Все заявки поступают в единый кадровый чат Telegram.
* **Персистентный FSM:** прогресс заполнения анкет кандидатами сохраняется в SQLite и не теряется при перезапусках бота или обновлениях кода.
* **Мост прямого диалога (Live Chat):** возможность кадровика открыть сквозной анонимный чат с кандидатом из любого поддерживаемого мессенджера прямо через Telegram.
* **Встроенная Git-панель (`/git`):** обновление кода из GitHub (`git pull`) с автоматическим перезапуском в один клик, откат ревизии на 1 коммит назад (`HEAD~1`), мгновенный возврат к актуальному коммиту GitHub и переключение веток (`main` / `beta`).
* **Модуль экстренной техподдержки (`/support`, `/sos`):** соискатели могут отправить прямое сообщение дежурному инженеру в обход кадрового чата в случае технических трудностей.
* **Служебные заметки кадровика:** возможность прикреплять текстовые пометки к анкете кандидата (`admin_note`) прямо из интерфейса карточки.
* **Динамическое меню по ролям:** интерфейс главного меню адаптируется под статус пользователя (соискатель, кадровик, инженер, главный администратор).
* **Горячее резервное копирование и экспорт:** создание резервных копий базы данных по расписанию и по требованию (`/backup`), а также экспорт кандидатов в Excel (`/export`).

## ⚖️ Соответствие Федеральному закону № 152-ФЗ

1. **Явное согласие на обработку ПДн (ст. 9):**
   * Соискатель обязан подтвердить согласие нажатием инлайн-кнопки перед заполнением анкеты или отправкой вопроса.
   * Фиксируются дата, точное время получения согласия и версия соглашения (`consent_timestamp`).
2. **Безвозвратное уничтожение данных (ст. 21):**
   * При удалении анкеты кадровиком запись стирается из базы данных SQLite с затиранием дисковых страниц (`PRAGMA secure_delete = ON`).
   * Перед физическим удалением автоматически создаётся защитная копия базы.
   * Соискатель получает официальное уведомление об уничтожении его персональных данных в соответствии с регламентом.
3. **Защита в режиме `PROD`:**
   * В боевом режиме доступ к персональным данным ограничен только участниками кадрового чата.
   * Действует автоматический 3-месячный кулдаун на повторную подачу анкеты при отказе.

## 👥 Роли и команды бота

### Соискатель
* `/start` — главное меню (подача анкеты, FAQ, контакты депо).
* `/apply` — заполнение анкеты на вакансию.
* `/my` — просмотр статуса поданной заявки.
* `/ask` — задать вопрос отделу кадров.
* `/faq` — ответы на часто задаваемые вопросы (обучение, зарплата, жилье, документы).
* `/contacts` — телефоны и адреса отдела кадров и депо.
* `/support`, `/sos` — экстренная связь с техническим администратором.
* `/privacy` — политика обработки персональных данных.
* `/cancel` — отмена текущего ввода или опроса.

### Отдел кадров (HR)
* `/admin` — панель кадровой статистики и списки активных анкет.
* `/export` — выгрузка базы резюме кандидатов в Excel (.xlsx/.csv).
* `/set_group` — привязка рабочего кадрового чата.
* `/block`, `/unblock` — управление блокировкой нарушителей.

### Технический инженер (Tech / DevOps)
* `/tech` — технический мониторинг системных метрик, аптайма, здоровья SQLite и статуса шлюзов.
* `/status`, `/refresh` — мгновенное обновление системных метрик в реальном времени.
* `/git`, `/deploy`, `/github` — панель управления репозиторием и обновлениями службы.
* `/restart`, `/reboot` — быстрый перезапуск системной службы бота.
* `/backups` — список и управление резервными копиями базы данных.
* `/logs` — просмотр системного журнала событий прямо в Telegram.
* `/admins` — управление списком администраторов и инженеров.

## 🏛 Модульная структура проекта

```text
uetbot/
├── bot.py                  # Главная точка входа: инициализация, роутеры, шлюзы
├── common.py               # FSM-состояния, синглтоны bot/dp/db, системные метрики
├── keyboards.py            # Инлайн- и реплай-клавиатуры для всех сценариев
├── config.py               # Загрузка и валидация конфигурации .env
├── database.py             # СУБД SQLite (WAL-режим, асинхронные очереди, автобэкапы)
├── texts.py                # Текстовые константы, шаблоны уведомлений и FAQ
├── deploy.py               # Кроссплатформенный менеджер развертывания
│
├── handlers/               # Модульные обработчики Telegram (aiogram 3 Router)
│   ├── candidate.py        # Сценарии соискателя: опросник, FAQ, поддержка, статус
│   ├── hr.py               # Кадровая служба: карточки соискателей, статусы, диалоги
│   └── tech.py             # Инженерная панель: мониторинг, Git, логи, бэкапы

│   ├── vk_gateway.py       # Автономный шлюз ВКонтакте (Long Poll API)
│   └── max_gateway.py      # Шлюз корпоративного мессенджера МАКС (MyTeam / VK Teams)

├── docs/                   # Техническая документация и архитектурные решения

│   ├── glossary.md         # Глоссарий предметной области
│   └── adr/                # Архитектурные решения (ADR 001 - 004)
│
├── requirements.txt        # Список зависимостей Python
└── uet_bot.service         # Конфигурация системной службы Linux systemd
