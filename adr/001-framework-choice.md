# ADR 001: Выбор стека разработки — Python 3.11+ и фреймворк aiogram 3.x

- **Статус:** Принято (Accepted)
- **Дата:** 2025-10-15
- **Автор:** Главный архитектор проекта (Principal Architect)
- **Область действия:** Архитектура бэкенда и Telegram-бота АИС «УЭТ-Бот»
- **Стандарт:** Architecture Decision Records (Michael Nygard format)

---

## Контекст и проблематика

Муниципальное унитарное предприятие «Ульяновскэлектротранс» (МУП «УЭТ») осуществляет масштабную программу цифровой трансформации и модернизации кадрового подбора на городском электрическом транспорте (трамваи «Львенок», троллейбусы «Адмирал»). Перед архитектурной группой встала задача создания высоконадежного, отказоустойчивого и масштабируемого сервиса автоматизации первичного рекрутинга, приема обращений соискателей и оперативного диспетчерского информирования.

Ключевые технические и эксплуатационные вызовы проекта:
1. **Высокая конкурентность и асинхронный ввод-вывод:** Обработка сотен одновременных диалогов с кандидатами, фоновое взаимодействие с API Telegram, шлюзами ВКонтакте и веб-панелью операторов депо.
2. **Сложная логика диалоговых состояний (FSM):** Опросник соискателя включает 16 последовательных шагов (ФИО, дата рождения, водительские удостоверения, опыт, предпочтительное депо, сменный график), требующих строгой валидации и возможности возврата или пропуска шагов.
3. **Безопасность и 152-ФЗ РФ:** Необходимость полного контроля над обработкой и хранением данных в защищенном контуре предприятия без скрытых сторонних телеметрий.
4. **Простота сопровождения штатным IT-отделом предприятия:** Ограниченный штат технических специалистов требует применения широко распространенного языка с прозрачным синтаксисом и богатой экосистемой.

## Рассмотренные альтернативы

### Альтернатива 1: Node.js / TypeScript + Telegraf.js
- *Преимущества:* Высокая скорость событийно-ориентированного цикла (Event Loop), отличная экосистема для веб-приложений.
- *Недостатки:* Меньшая распространенность в корпоративном секторе региональных муниципальных предприятий. Сложности с интеграцией отечественных библиотек генерации юридических документов (docx/pdf по ГОСТ), отсутствие встроенной развитой модели конечных автоматов для сложных кадровых сценариев уровня aiogram FSM. Повышенные накладные расходы на типизацию и поддержку среды выполнения Node.js.

### Альтернатива 2: Python + pyTelegramBotAPI (telebot)
- *Преимущества:* Низкий порог входа, простота написания процедурных скриптов.
- *Недостатки:* Исторически синхронная архитектура, плохая масштабируемость при высоких нагрузках. Асинхронный модуль `telebot.async_telebot` является надстройкой и уступает в надежности. Отсутствие нативного механизма middleware, слабая поддержка типизации Python (type hints) и жесткая привязка к устаревшим паттернам проектирования.

### Альтернатива 3: Python + python-telegram-bot (PTB)
- *Преимущества:* Зрелая библиотека, поддержка `asyncio`, обширная документация.
- *Недостатки:* Избыточная монолитность архитектуры, сложная и громоздкая система `ConversationHandler`, уступающая по гибкости роутерам и фильтрам aiogram 3. Сложнее интегрировать сторонние веб-панели на FastAPI/Aiohttp в едином цикле событий (Event Loop).

### Альтернатива 4: Python 3.11+ + aiogram 3.x (Выбранное решение)
- *Преимущества:* Полностью асинхронный фреймворк, изначально спроектированный под архитектуру `asyncio`. Модульная система роутеров (`Router`), изолированные middleware на этапах `pre-process`, `process` и `post-process`. Мощный встроенный движок FSM (`FSMContext`) с поддержкой сменных бэкендов хранения состояний. Нативная поддержка Pydantic v2 и строгой типизации Python 3.11+, гарантирующая выявление ошибок на этапе компиляции и статического анализа.

## Архитектурное решение

Принято решение утвердить технологический стек **Python 3.11+ и aiogram 3.x** в качестве официального корпоративного стандарта для разработки АИС «УЭТ-Бот».

Обоснование решения:
1. **Производительность Python 3.11+:** Улучшенный интерпретатор CPython 3.11+ с оптимизацией Faster CPython обеспечивает прирост скорости выполнения асинхронного кода на 25-40% по сравнению с Python 3.9/3.10.
2. **Модульная маршрутизация (Router Architecture):** Разделение обработчиков на независимые изолированные роутеры (`candidate_router`, `admin_router`, `tech_router`) обеспечивает соблюдение принципа единственной ответственности (Single Responsibility Principle) и параллельную разработку модулей несколькими инженерами.
3. **Унифицированный жизненный цикл FSM:** `CandidateForm` управляет 16 состояниями анкетирования с возможностью очистки контекста (`state.clear()`), промежуточного сохранения в SQLite и защиты от несогласованных данных при обрыве связи соискателем.
4. **Бесшовная интеграция с веб-панелью aiohttp:** Возможность одновременного запуска Telegram Long Polling, веб-сервера управления предприятием и фоновых планировщиков (APScheduler) в рамках одного процесса и одного цикла событий без межпроцессных блокировок.

## Последствия (Consequences)

### Положительные последствия:
- **Высокая пропускная способность:** Система способна обрабатывать пиковые нагрузки до 500 одновременных диалогов без роста задержек отклика (< 200 мс).
- **Чистота кодовой базы:** Использование современных конструкций Python (типизированные кортежи, паттерн-матчинг, асинхронные генераторы) существенно снижает технический долг.
- **Стандартизированная пирамида тестирования:** Архитектура хэндлеров aiogram 3 позволяет легко изолировать обработчики и выполнять быстрое модульное тестирование с подменой `FSMContext` (MemoryStorage) без обращений к реальному Telegram Bot API.

### Отрицательные последствия и минимизация рисков:
- *Риск:* aiogram 3 имеет существенные отличия от устаревшего aiogram 2.x, что может потребовать переобучения персонала.
  *Митигация:* Разработаны исчерпывающие руководства разработчика, архитектурные диагнозы и матрица трассируемости требований.
- *Риск:* Асинхронное программирование требует жесткого контроля за блокирующими вызовами в цикле событий (I/O Bound).
  *Митигация:* Все файловые и тяжелые операции вынесены в пулы потоков (`asyncio.to_thread` / `run_in_executor`), операции БД выполняются через оптимизированный режим SQLite WAL с таймаутами.
